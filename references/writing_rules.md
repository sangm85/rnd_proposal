# Writing Rules

## Default Writing Guide

- Use Korean government R&D proposal style: concise, evidence-oriented, implementation-focused.
- Prefer `~함`, `~됨`, `~추진함`, `~확보함`, `~검증함`, `~고도화함` for submission-ready drafts.
- Make the evaluator's verification path visible: requirement -> proposed work -> method -> output -> KPI -> validation.
- Quantify when possible. If a number is unknown, write `[기입 필요]` and keep the sentence structure intact.
- Avoid unsupported claims such as `세계 최초`, `독보적`, `획기적`, `완벽한`, `최고 수준`.
- Explain AI as part of a data-processing-validation-service chain, not as a standalone buzzword.
- Separate institution roles clearly. Do not let two institutions appear responsible for the same final deliverable unless governance is explained.

## Reference-Based Guide

When reference proposals are provided, extract only writing rules:

- tone and ending style
- paragraph order
- common transition phrases
- KPI expression pattern
- evaluation response sentence pattern
- technical explanation depth
- table and diagram style

Do not copy reference content, examples, proprietary details, names, numbers, or claims unless the user explicitly says they belong to the current project.

## Paragraph Pattern

A strong paragraph usually contains:

1. purpose or problem
2. development target
3. data or input
4. technical method
5. implementation approach
6. validation method
7. expected output or service linkage

Do not expose this as a rigid template unless the user asks. Convert it into natural proposal prose.
