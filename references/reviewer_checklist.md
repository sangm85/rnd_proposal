# Reviewer Checklist

Always review after drafting. Report findings in `충족 / 보완 필요 / 기입 필요`.

## Required Checks

- 개발 흐름이 자연스럽게 연결되는가
- 입력/처리/출력 구조가 설명되는가
- 검증 방법이 포함되는가
- 실증 활용 방향이 포함되는가
- 단순 `개발한다` 수준에서 끝나지 않는가
- 평가위원 관점에서 이해 가능한가
- RFP 필수 요구사항이 누락되지 않았는가
- 평가항목 대응 위치가 분명한가
- 정량 KPI가 baseline, target, 측정방법, 검증주체를 갖추었는가
- 기관별 역할이 중복되거나 충돌하지 않는가
- 과장 표현이나 근거 없는 우수성 표현이 없는가
- 기술 설명이 지나치게 표 중심으로 처리되지 않았는가
- 추상적 표현이 구체적 수행방법으로 보완되었는가
- 산출물, 연차 계획, 검증 계획이 서로 모순되지 않는가

## Revision Direction

For each issue, state:

- where the issue appears
- why it matters for evaluation
- how to revise it
- what missing input is needed, if any
